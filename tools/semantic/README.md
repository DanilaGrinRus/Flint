# Semantic search по `crates/`

Смысловой поиск по исходникам Flint: эмбеддинги считает локальная модель в
LM Studio, наружу ничего не уходит. Дополняет `grep`, а не заменяет его —
находит места по смыслу («где вообще проверяется истечение таймлока»), а не по
точному имени символа.

## Запуск

```powershell
pwsh -File tools/semantic-search.ps1 -Rebuild                     # собрать индекс
pwsh -File tools/semantic-search.ps1 "slate construction"          # английский запрос
pwsh -File tools/semantic-search.ps1 "таймлок истёк, возврат монет"  # русский, без перевода
pwsh -File tools/semantic-search.ps1 -Ru "где формируется slate"   # перевод через 14B (опция)
```

Требуется загруженная в LM Studio модель **`text-embedding-bge-m3`** (Q8_0,
634 МБ, многоязычная). Python резолвится так: `-Python` → `FLINT_PYTHON` →
`python` из `PATH` (нужен `numpy`); эндпоинт и модель меняются через
`-Endpoint` / `LMSTUDIO_URL` и `LMSTUDIO_EMBED_MODEL`.

## Проверка модели перед запуском

LM Studio должен быть запущен, а в нём загружена **`text-embedding-bge-m3`**.
Быстрая проверка:

```powershell
# какие модели загружены
(Invoke-RestMethod http://127.0.0.1:1234/v1/models).data.id

# какой эмбеддер реально обслуживает запросы: 1024 — bge-m3, 768 — nomic
$body = @{ model = 'text-embedding-bge-m3'; input = @('проверка') } | ConvertTo-Json -Compress
(Invoke-RestMethod http://127.0.0.1:1234/v1/embeddings -Method Post `
  -ContentType 'application/json' -Body $body).data[0].embedding.Count
```

- `1024` — активен `bge-m3`: можно строить индекс и искать по-русски без `-Ru`.
- `768` — активен `nomic-embed-text`: выгрузить его (и другие лишние эмбеддеры)
  в LM Studio, повторить проверку и пересобрать индекс с `-Rebuild`.
- Ошибка соединения — LM Studio не запущен.

`GET /v1/models` перечисляет загруженные модели, но не говорит, какая из них
обслуживает эмбеддинги: поле `model` в `/v1/embeddings` LM Studio игнорирует
(см. «Ограничения»). Поэтому ориентир — размерность ответа, а не список имён.
Для `-Ru` дополнительно нужен загруженный `qwen2.5-coder-14b-instruct`.

## Как устроено

| Файл | Назначение |
|---|---|
| `common.py` | модель, эндпоинт, каталог индекса, префиксы задач, HTTP-обёртки |
| `index.py` | режет `crates/**/*.rs` на окна по 32 строки с перекрытием 8 и считает эмбеддинги |
| `query.py` | кодирует запрос, считает косинус, печатает топ-N с `путь:строки` |
| `.tmp\semantic\index.npz`, `meta.json` | результат индексации (4.8 МБ + 1.6 МБ), в поставку не входит |

Размерность берётся из ответа эмбеддера, поэтому модель можно менять без правок
кода: `LMSTUDIO_EMBED_MODEL=<id> pwsh -File tools/semantic-search.ps1 -Rebuild`.
Индекс по умолчанию лежит в `.tmp\semantic\`: `tools/` в этой сессии доступен
только на чтение. Каталог меняется через `-IndexDir` или `FLINT_SEMANTIC_INDEX`.

83 файла → 1310 кусков; сборка индекса на `bge-m3` ~23 с (на `nomic` было ~13 с),
запрос ~0.4 с.

## Что показал A/B на одних и тех же запросах

`bge-m3` (Q8_0) против `nomic-embed-text` (Q4_K_M), русские запросы **без**
перевода через LLM:

| Запрос | `bge-m3` | `nomic` Q4 |
|---|---|---|
| «где формируется slate для транзакции» | `rpc_backend.rs:889` (`let slate_id = slate`) | `service.rs:1873`, `rpc_backend.rs:865` |
| «проверка баланса после сканирования» | `wallet.rs:169`, `scan.rs:145`, `service.rs:1177` | `service.rs:2785`, `1129`, `model.rs:73` |
| «подключение к ноде через Tor» | `tor.rs:145`, `slint-ui/main.rs:169` | `tor.rs:121`, `slint-ui/main.rs:169` |
| «где проверяется, что таймлок истёк, перед возвратом монет» | `janus/service.rs:217`, `janus/model.rs:313` (тесты) | `messenger/error.rs`, `seed/envelope.rs` — промах |

Вывод: `bge-m3` не хуже и на одном запросе заметно лучше, при этом не требует
переводчика. Связка `nomic` + перевод 14B давала лучшее попадание на запросе про
таймлок (`model.rs:265-296`, `refund_available`), но держит 9 ГБ видеопамяти
ради одного шага — поэтому она осталась опцией `-Ru`, а не путём по умолчанию.

## Ограничения (проверено прогонами)

- **LM Studio обслуживает один эмбеддер за раз.** Поле `model` в `/v1/embeddings`
  игнорируется: `text-embedding-bge-m3`, `nomic-embed-code` и даже несуществующий
  id возвращают один и тот же вектор (проверено побайтово). Поэтому A/B моделей
  возможен только по одной загруженной: выгрузи лишние в LM Studio, иначе индекс
  молча соберётся чужой моделью — размерность совпадёт, а результаты будут
  обманывать.
- **`nomic-embed-code` (GGUF от lmstudio-community) как эмбеддер не работает.**
  LM Studio грузит его с `type: "llm"` (arch `qwen2`, capabilities `tool_use`), и
  `/v1/embeddings` отвечает `400 No models loaded`, хотя чат с ним идёт. Для
  сравнения нужен GGUF с pooling-конфигом или llama.cpp с `--embedding`.
- **Точный символ ищется лучше, чем пересказ.** Запрос `refund_available` даёт
  `janus/model.rs:265-296` первым местом; пересказ «таймлок истёк, возврат
  монет» — только тесты, потому что в самом коде про возврат написано
  по-английски (`Whether the refund path is currently legal`). Для точных
  имён `grep` надёжнее.
- **Контекст эмбеддера.** `bge-m3` умеет 8192, но в LM Studio может загрузиться
  с 2048 — для окон по 32 строки (~400–600 токенов) этого достаточно; окна
  больше ~60 строк на 2048 уже обрезаются.
- **Префиксы.** `nomic` требует `search_document:`/`search_query:`, `bge-m3` —
  нет; `common.py` включает их только для моделей с `nomic` в имени.
- Границы функций не соблюдаются: окно может разрезать `match` или `impl`,
  поэтому найденный диапазон — указатель, а не готовый контекст.
- Индекс статический: после правок кода его надо пересобирать (~23 с).
- `-Ru` требует загруженного `qwen2.5-coder-14b-instruct`; без него печатает
  предупреждение и ищет по оригиналу.
- Это dev-инструмент: он не входит в `cargo`-сборку, не влияет на `tools/ci.ps1`
  и не требует сетевых зависимостей проекта.
