# Политика инцидентов

Статус: **черновик до публичного релиза**. Контакт для сообщений и канал
публикации ещё должны быть утверждены владельцем проекта.

## Область

Уязвимости, потеря/кража seed, компрометация релизного артефакта, утечка
переписки, ошибки подписи/публикации транзакций и проблемы, затрагивающие
пользовательские средства.

## Сообщение об инциденте

- Публичный канал: **TBD** (security-контакт и, при наличии, PGP-ключ).
- Не открывать детали эксплуатации в общем чате до подтверждения.
- В сообщении: версия/хеш сборки, ОС, шаги, эффект, есть ли средства под угрозой.
- Подтверждение получения — в течение 3 рабочих дней; первичная оценка — 7 дней.

## Северity

| Уровень | Пример | Реакция |
|---|---|---|
| Critical | кража/потеря средств, утечка seed | немедленно, остановить публикацию/отзыв |
| High | обход runtime-проверки, подмена slate | 24–72 часа |
| Medium | утечка метаданных, DoS | 7 дней |
| Low | UI/документация | следующий релиз |

## Отзыв сборки

1. Зафиксировать затронутые версии и SHA-256 артефактов.
2. Опубликовать advisory с impact, обходом и новым хешем.
3. Снять zip с каналов распространения; не перезаписывать старый файл.
4. Собрать новый артефакт из чистого коммита/дерева, проверить `sha256` и
   `flint-selftest`.
5. Ротировать ключи/пароли, если инцидент затрагивает подпись или seed.
6. Уведомить пользователей о необходимости проверить адрес получателя и
   истории транзакций.
