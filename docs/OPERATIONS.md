# Эксплуатация и данные

Кошелёк — DEV/testnet. [STATUS.md](STATUS.md) фиксирует готовность,
[SECURITY.md](SECURITY.md) — обязательные ограничения. Смена структуры исходников
не переносит, не сбрасывает и не переименовывает пользовательские данные.

## Установка, обновление и откат

Сверить полные SHA-256 пакета, exe и source с его манифестом. Распаковать RC в
новый каталог; рядом должны быть resources, runtime DLL, BUILD-INFO, hashes,
SBOM, исходники и лицензии. Unsigned RC явно помечен: Windows может показать
SmartScreen. Запуск для проверки:

```powershell
.\Flint.exe --data C:\Flint-Testnet-Disposable
```

Обновление: завершить операции, закрыть Flint, сделать проверенную копию данных,
распаковать новый пакет рядом с прежним, сверить hashes, открыть явно выбранный
testnet root и проверить профиль/адрес/состояния. Не перезаписывать единственный
рабочий пакет до этой проверки. Откат binary через forward-only миграцию требует
предмиграционной копии данных; замена exe сама по себе данные не откатывает.

## Корень данных и профили

Portable использует `data` рядом с exe; без portable-маркера —
`%LOCALAPPDATA%\Flint`. `--data` и `FLINT_DATA_DIR` имеют приоритет над настройкой.
В root разделены сети/профили: wallet/wallets, node, pending/state, RPC,
messenger/history. Именованные профили имеют независимые seed, пароль и историю;
одновременно в окне активен один профиль. Default сохраняет прежний путь.
Две одновременные копии одного seed не являются multiwallet.

Выбор нового абсолютного каталога в настройках применяется при перезапуске.
Flint не копирует и не удаляет прежние данные. Пустой новый root выглядит пустым
кошельком/цепью и не доказывает потерю старого. Portable-селектор `data-root.json`
лежит рядом с exe вне data; в обычном режиме — в стандартном LOCALAPPDATA root.
Повреждённый/относительный selector даёт ошибку, не тихое открытие другого кошелька.
Исправлять selector только при закрытом приложении.

Перенос по отдельному решению: завершить операции, закрыть приложение, скопировать
полный root с сохранением структуры, выбрать копию, перезапустить, сверить профиль
и адрес и выполнить полный scan. Оригинал сохранять до независимой проверки.
Mainnet-каталоги в текущей работе не переносятся и не открываются.

## Каталоги DHW, которые не являются мусором

| Путь | Назначение и правило |
|---|---|
| `.node/` | Рабочая testnet chain DB и node config/secrets. Не build cache; заново синхронизировать только по отдельному решению. Работающая нода не останавливается ради уборки target. |
| `fixtures/` | Существующие funded disposable testnet-кошельки и приёмочные данные; не пересоздавать автоматически |
| `dist/data/` | Найденные данные кошелька в выходном каталоге; не удалять вместе с пересобираемым dist |
| `archive/archV/legacy-data/` | Сохранённые legacy-данные; имя archive не означает разрешение удаления |
| `mobile/grinflint-backups/` | Мобильные backup-данные, отдельные от iOS build cache |
| `.secrets/` | Локальные секреты. Не печатать, не включать в source/package/Git |
| `_acl-recovery/` | Материалы отката ACL, если они ещё нужны для восстановления; удаление после отдельной проверки |
| `docs/testnet-funded.txt`, `docs/grinflint-ci-wallet.txt` | Осознанно открытые реквизиты одноразовых faucet/testnet-кошельков; не реальные секреты пользователя |
| `vendor/` | Нужен текущему offline Cargo-режиму; это зависимости, не пользовательский код и не обычный target cache |
| `third_party/`, `resources/` | Закреплённые/проверяемые исходники и runtime assets, необходимые для сборки/поставки |

Рабочая установленная копия `C:\Flint` находится за пределами проекта; её `data`
и `data1` не участвуют в уборке. В `data1` ранее отмечены mainnet-данные.
Содержимое секретов для определения назначения каталогов не выводится.

## Backup и восстановление

24 слова/поддерживаемая upstream seed-фраза дают доступ к средствам; пароль
защищает локальный конверт. Backup проверяется восстановлением, а не наличием файла.
Фраза не отправляется в чат, лог и облако в открытом виде. Копия wallet_data
не заменяет seed/envelope; seed не расшифрует прежнюю историю messenger.

1. Записать сеть, профиль, версию и адрес без seed; сохранить проверенный backup.
2. Восстановить в чистый отдельный testnet root с новым паролем.
3. Дождаться полного scan: до него баланс неизвестен. Partial restore scan запрещён.
4. Сверить адрес и spendable/awaiting/total/immature/locked с ожидаемым состоянием.
5. Повторить на отдельном устройстве по D-10. Несовпадение адреса — остановиться,
   сохранить исходники/копию данных и диагностировать без публикации seed.

Переписка/контакты требуют собственной копии history/keywrap. Старую историю
восстанавливают отдельной функцией и старым паролем; ошибка истории не должна
создавать новый wallet или затирать существующий ключ. TTL-удалённые сообщения
из seed не возвращаются. Старый data root не удалять при забытом пароле.

## Нода и testnet-стенд

```powershell
pwsh -File tools/run-testnet-node.ps1 start
pwsh -File tools/run-testnet-node.ps1 status
pwsh -File tools/run-testnet-node.ps1 stop
```

Команды применяются к явно выбранному testnet-стенду. В UI нода готова только
после проверки сети и завершения синхронизации; отсутствие соединения — не
доказанный нулевой баланс. Чужой процесс на порту не завершается автоматически.
Сценарий физических аварий — [ACCEPTANCE.md](ACCEPTANCE.md#f04).

## Messenger, Tor и relay

Пустой relay_url при активном «Приём по Tor» выбирает direct onion;
получатель должен быть онлайн. В desktop этот режим связан с RPC foreign API.
Заполненный relay_url использует gateway/relay, который может хранить конверт
для офлайн-получателя до TTL. Адрес/onion берётся из ключа slatepack, owner API
наружу не публикуется. Успех транспорта не означает подтверждение перевода.
Автообработка slatepack opt-in и только для сохранённых контактов.

Локальный relay:

```powershell
cargo build --release -p flint-core --bin flint-relay
.\target\release\flint-relay.exe --listen 127.0.0.1:8080 --store C:\FlintRelay\store --ttl 93600 --max-per 100 --max-total 10000
Invoke-WebRequest http://127.0.0.1:8080/flint/v1/health
```

Relay не содержит seed/кошелька, foreign API возвращает 404. Для публикации нужен
Tor hidden service к loopback либо TLS reverse proxy; plain HTTP `0.0.0.0`
с секретными API не открывать. Публичный relay-сервис в этот RC не входит.
Протокол/квоты/подписанный ACK — [contracts/MESSENGER.md](contracts/MESSENGER.md).

Для блокируемых сетей Tor читает `<data>/<network>/tor/bridges.txt`.
Поддерживаются obfs4/snowflake/webtunnel через `lyrebird.exe` из Tor expert bundle
либо `FLINT_LYREBIRD_BIN`. Строки получать у Tor Project, не публиковать в логах;
автоматической загрузки нет. При отсутствии клиента или нечитаемом файле — явная
ошибка. UI позволяет сохранить мосты/перезапустить Tor и увидеть его диагностику.
На Windows Tor использует подходящий ASCII/8.3 путь при Unicode-ограничении
его DataDirectory; живой успех конкретного внешнего моста нельзя выводить из
проверки синтаксиса torrc. `.onion` использует SOCKS запущенного Tor или
`FLINT_TOR_SOCKS`, обычно `127.0.0.1:9050`.

## Временные результаты и уборка

Пересобираемы target, промежуточные packages, source snapshots и обычные .tmp-логи.
Они не смешиваются с перечисленными выше данными. Перед удалением проверяются
абсолютные пути, reparse points, отсутствие используемого файла и единственной
копии исходников/evidence. Выполненные shell-команды не заменяют проверку результата.

Свидетельства принятого RC — `evidence/rc-20261029`, полный rollback уборки временно
создаётся вне канонической документации и затем выносится из активного дерева.
После удаления target/.tmp следующие сборки пересоздают их; offline vendor остаётся.
Не запускать blanket cleanup dist/archive/mobile по одному имени каталога.
