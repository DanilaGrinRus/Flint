# Безопасность и ограничения

Локальный аудит desktop+iOS от 30.10.2026: [отчёт и результаты](../evidence/audit-20261030/REPORT.md).
Подтверждены внутренние P1 iOS (restore/journal/finalize) и P2 desktop
(привязка API-секрета к endpoint, receive-cache, RPC config, Nostr URL).
Desktop P2 исправлены 30.10.2026 (см. «Исправления аудита 30.10.2026» и
`evidence/security-fixes-20261030/README.md`); iOS P1 остаются в mobile/GrinFlint.
Тесты не опровергают эти находки; физическая приёмка и mainnet не подтверждены.

**DEV BUILD. Не аудирован. Не для реальных средств. Только testnet.**
Готовность RC к внешним устройствам не разрешает mainnet или production.
Внешний аудит исключён из текущей задачи и не добавляется к её остатку.
Уборка файлов не является проверкой безопасности.

## Граница доверия

Slint и runtime — один процесс: malware, дамп памяти или пользователь с доступом
к процессу могут видеть его секреты. Граница UI/runtime предотвращает обычный
обход проверок, но не создаёт изоляцию ключей. Все денежные действия повторно
проверяются в runtime; состояние кнопки не является разрешением операции.

- UI не вызывает owner RPC/HTTP и не читает seed-файл напрямую.
- Seed/пароль живут в UI только для необходимого ввода/показа; поля очищаются
  при закрытии, переключении и блокировке. Zeroizing не гарантирует очистку
  всех копий строк графической библиотеки или системного swap.
- Пароли, mnemonic, секретные nonce/keys, node/owner secrets, полный чувствительный
  armor не выводятся в ошибки, логи, telemetry, screenshots или diagnostics.
- Непроверенные RPC/FFI/файловые данные валидируются на входе; повреждённый
  журнал/кошелёк не подменяется пустым состоянием и не перезаписывается.
- Owner API — loopback+auth. Secret по remote plain HTTP не передаётся;
  внешняя нода требует явной безопасной конфигурации и проверки сети.
- Запись private-файла: уникальный temp, ограниченные права до записи,
  durable write/flush, атомарное продвижение и проверка конечных прав.
  Ошибка ACL должна быть обработана, а не подавлена предупреждением.
- В Windows DACL заменяется с исключением чужих явных ACE; гарантия на ФС без
  ACL задаётся явной политикой и отдельно проверяется на устройстве.

## Секреты и миграция

Конверт seed — [contracts/SEED.md](contracts/SEED.md). Главные свойства:
сверка фактического адреса до удаления legacy, поддерживаемая версия/сеть,
ограниченный KDF до выделения памяти, новые salt/nonce, явное согласие на
миграцию/очистку старых слабых копий, отсутствие удаления чужого seed.
Установленная версия программы сама по себе не мигрирует legacy-данные.

Межпроцессный writer, локальный malware, TOCTOU при праве записи в каталог,
core dumps/swap и crash diagnostics остаются пределами модели. Не запускать
несколько процессов с одной wallet DB; интерфейсный single-instance guard
не является доказательством изоляции от внешнего grin-wallet. Power-loss
не равен process kill; физические гарантии проверяются отдельно.

в SBOM отражаются Cargo и поставляемые binaries/DLL. Hash manifest рядом с exe
не является независимой подписью поставки. Текущий RC unsigned.

## Messenger v1

Содержимое шифруется, но relay видит получателя, размер, время и может проверить
гипотезу об отправителе по открытой подписи. Forward secrecy/ratchet нет:
компрометация долгосрочного ключа получателя угрожает старой переписке.
Подписанный ACK, durable inbox/outbox и локальные tombstones решают другие задачи
и не делают транспорт анонимным. Полный [контракт](contracts/MESSENGER.md).

## Janus: отложенная безопасность

Runtime использует demo в памяти. До подключения реальных свопов нужно отдельное
решение/приёмка. В review 2026-10-28 были зафиксированы: ошибочный file read→пустая
история, with_parts без загрузки snapshot, публикация памяти до save, LockGrin
до VerifyStamps, непроверенный RevealSecret, необязательная сумма/fail-open
границы и риск коллизии short_id. Это сохранённый список требований будущего
трека, не вновь воспроизведённые дефекты текущего RC.

Снимок свопа нельзя молча обнулять при corruption; состояние публикуется после
успешной записи; lock сверяется с оффером/сетью/суммой, reveal требует доказательства,
refund не теряется от произвольного сообщения. Историческая находка «Rust rename
на Windows вообще не перезаписывает цель» была опровергнута и не должна возвращаться
как критичная. Реальный atomic swap текущими тестами не подтверждён.

## Исправления аудита 30.10.2026

- **Секрет ноды (D-A1).** Managed `.api_secret` читается только для literal
  loopback (`localhost`, 127.0.0.0/8, ::1). Внешняя нода без явного секрета его
  не получает; `rpc_backend` не прописывает этот путь в `grin-wallet.toml` и
  очищает stale `node_api_secret_path`. Сохранённый `http://` внешний адрес при
  загрузке заменяется локальной нодой с предупреждением. Инвариант: bearer-секрет
  не пересекает границу хоста.
- **Повтор receive (D-A2).** Embedded и RPC журналы хранят canonical JSON
  исходного S1; повтор с тем же slate id и другим содержимым отклоняется. Записи
  без отпечатка (legacy) повтор не разрешают — fail-closed.
- **Отправка при догоняющей ноде.** `Headers`/`Blocks` не разрешают подпись
  автоматически: UI обязан показать предупреждение и получить явный чекбокс,
  иначе `send_sync_gate` отказывает. `Starting`/`Unknown`/`NotRunning` запрещены
  всегда. Цепь остаётся арбитром, но приложение не создаёт заведомо обречённую
  операцию с заблокированной сдачей.
- **Подтверждение отправки.** `prepare` сохраняет digest S1 и контекст
  (network/address_index/destination/amount/fee) в журнале и отдаёт UI opaque
  token. `finalize` без совпадения токена, контекста, сумм или digest не
  подписывает; старые pending без маркера fail-closed. Автофинализация
  ответов на отправку из messenger больше не подписывает: она уходит в
  `needs_review`.
- **Устаревший журнал после восстановления backup.** Перед новой подписью
  backend обновляет outputs из ноды и сверяет входы S1. Потраченный или
  ненайденный вход переводит запись в `failed_recoverable` и запрещает
  подпись; цель — не создавать заведомо отвергаемую сетью операцию и не
  блокировать сдачу.
- **RPC-конфиг (D-A3).** Ошибки чтения/записи `grin-wallet.toml` больше не
  проглатываются; запуск завершается ошибкой вместо работы со старой
  конфигурацией, которую проверка готовности уже не использует.
- **Nostr relay (D-A4/D-A5).** URL проверяется разбором host, а не префиксом:
  `ws://` разрешён только для literal loopback. Бюджет 10 с покрывает DNS, TCP,
  TLS и WebSocket handshake; кадры ограничены 1 MiB/256 KiB, query — 4096
  сообщений/8 MiB. DNS-резолв ОС не прерывается: вызов возвращается по бюджету,
  но зависший resolver может оставить helper-поток.

Проверки: `cargo test -p flint-core --lib` 195, `cargo test -p flint-messenger`
83 (+1 ignored), `cargo test --workspace` 354 passed / 0 failed / 33 ignored.

## Инцидент и выпуск

При подозрении: прекратить новые денежные операции, сохранить исходные данные
и хэши/версию, изолировать проблему; не публиковать seed/пароль и не исправлять
коррупцию удалением pending/LMDB. Устойчивый security-контакт, PGP identity,
ответственные и production signing identity ранее не были утверждены.
Они относятся к самостоятельному публичному выпуску, не изображаются выполненными
и не добавляются в остаток согласованного unsigned testnet RC.

Для real funds/mainnet потребуется отдельное явное решение владельца и политика
приёмки; текущая работа такого решения не принимает. Даже малая сумма не является
разрешённым продолжением testnet-проверки.
