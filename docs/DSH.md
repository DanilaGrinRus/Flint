# DeepSeek Harness: работа с Flint

Общие правила — [AGENTS.md](../AGENTS.md), текущий статус — [STATUS.md](STATUS.md). Этот справочник описывает среду. Claude, его hooks/сабагенты и отдельные CLAUDE.md не используются.

## Профиль и загрузка инструкций

- Профиль находится в %USERPROFILE%\.dsh\profiles\desktop. Конфигурацию и учётные данные не копировать в проект/поставку; секреты не выводить.
- Проверка 2026-10-29: в профиле desktop пять прежних дополнительных пакетов 0.2.1-rc.3 (terminal-bundle, session-search, inspector-profile, plugin-market-bundle, subagent-codex) и три LSP-пакета, установленных в этой задаче (раздел о модулях ниже). Это датированная инвентаризация зависимостей, не доказательство активации каждого инструмента.
- Основные правила хранить в корневом AGENTS.md без истории прогонов; подробные контракты читать по необходимости. Произвольный корневой SKILL.md сам по себе не становится автоматически загруженной инструкцией.
- Desktop CWD: C:\DHW; iOS: mobile/GrinFlint с собственным AGENTS.md. Вложенные инструкции явно прочитать: cd внутри shell не гарантирует их загрузку.
- Проверять реальные доступные инструменты и установленную версию. Не считать наличие описания доказательством работоспособности.

## Работа с инструментами

1. Для длинной сборки открыть один постоянный терминал, создать короткий TMP и задать TMP/TEMP. Закрывать только свои завершённые терминалы. Короткие команды выполнять обычным shell-вызовом.
2. Если доступны jobs, независимую длинную команду запускать фоном и получать фактический результат после завершения. Cargo/упаковка/очистка одного дерева не конкурируют.
3. Большие задачи вести проверяемыми этапами. Goal/todo/plan, jobs, skills, spill/compaction предусмотрены текущей официальной базовой композицией; прежде дополнительной установки проверить доступность в своей версии.
4. session_search использовать для восстановления обсуждений; выводы проверять по текущему коду/статусу. Принятое решение фиксировать в каноническом документе.
5. Полный сырой вывод хранить временно; в контекст — итог. Принятое доказательство связывать с версией/коммитом/хэшем, сохранять компактно.
6. Семантический поиск — при неясном имени/смысле. bge-m3 загружать на время, проверять размерность 1024 и отсутствие другого эмбеддера; .tmp/semantic — восстанавливаемый индекс. См. [настройку](../tools/semantic/README.md).

## Делегации

subagent_codex разрешён владельцем для узких независимых разборов и второго мнения. Настройки модели/квоты проверять в окружении; постоянные названия моделей и размеры контекста в правилах не закреплять. Передавать цель, границы, пути и критерий результата; находки проверять по коду/тесту. Не передавать секреты и реальные кошельки.

## Дополнительные модули: решение Harness (2026-10-29)

Пользователь разрешил агенту решить по каждому кандидату самостоятельно. Проверено
на профиле desktop, DSH 0.2.1-rc.3 (hostProtocol 4): пакеты ставятся точно той же
версией `0.2.1-rc.3`, чужие rc/alpha в дерево не смешиваются.

| Кандидат | Решение | Основание кратко |
|---|---|---|
| dsh-lsp + dsh-lsp-stdio + dsh-tool-lsp | **УСТАНОВЛЕН** | Точная пара версий, есть rust-analyzer; навигация по Rust-символам подтверждена вызовом |
| dsh-experimental-tool-worktree | **ОТКАЗ** | Свежий checkout не собирается offline: `vendor/` игнорируется Git, а Cargo настроен на него с `net.offline = true` |
| computer-use (cua-driver-native) | **ОТКАЗ** | Экспериментальный native-драйвер в процессе хоста, управление реальным рабочим столом с рабочей установкой; не заменяет физические D-06…D-08 |
| Browser automation | **ОТКАЗ** | Нет веб-цели: UI Slint, Chromium его не проверяет |

### Установлено: LSP-навигация

- Пакеты `@deepseek-ai/dsh-lsp`, `dsh-lsp-stdio`, `dsh-tool-lsp` 0.2.1-rc.3
  (`dsh plugin --profile desktop add --save-exact`); бандла в поставке нет, поэтому
  строки добавлены в `cordis.patch.yml` профиля через `insert:`.
- Сервер — `rust-analyzer 1.99.1` из rustup (`rustup component add rust-analyzer`),
  абсолютный путь в конфигурации провайдера, `".rs": rust`; `timeoutMs: 180000`,
  потому что первый запрос ждёт загрузку рабочей области (~50 с).
- Проверки на реальном дереве — PASS: `goToDefinition` `crates/core/src/gateway.rs:279:16`
  → `crates/core/src/address.rs:20:8`; `hover` вернул сигнатуру и doc-comment;
  `findReferences` — 12 локаций, включая объявление; позиция вне символа → `No results.`;
  `README.md` → ошибка «no LSP provider handles», отсутствующий файл → ошибка чтения
  до запуска сервера. Вызов → результат → продолжение сессии выполнены.
- Ограничения: до конца индексации первый запрос может вернуть пустой результат
  (повторить); процесс rust-analyzer держит ~0,6 ГиБ RAM; компиляция proc-macro
  создаёт ignored `target/` ≈1,7 ГиБ (пересоздаваемый кэш; удаление возвращает
  размер к состоянию уборки, первый запрос после этого снова его строит); сервер
  исполняется с правами хоста без дополнительного sandbox; Slint/Swift не проверялись.
- Откат: копия конфигурации профиля — `C:\DHW-backups\dsh-profile-20261029\`
  (package.json, pnpm-lock.yaml, pnpm-workspace.yaml, cordis.patch.yml, cordis.yml).
  Удаление: убрать блок `- insert:` с LSP-строками и выполнить
  `dsh plugin --profile desktop remove @deepseek-ai/dsh-lsp @deepseek-ai/dsh-lsp-stdio @deepseek-ai/dsh-tool-lsp`.
- Модули живут в профиле Harness, не в поставке Flint: Cargo, vendor и лицензии
  проекта не меняются.

### Отказ: worktree

Польза — независимый checkout без копирования незакоммиченных файлов. Бандл
поставляется с DSH и выключен, отдельной загрузки не требует; отказ — из-за
неработоспособности checkout в этом репозитории. `vendor/` игнорируется Git
(1 050 MiB) и задан в `.cargo/config.toml` (`replace-with = "vendored-sources"`,
`net.offline = true`); проверка `git worktree add` + `cargo metadata --locked --offline`
завершилась `failed to load source for dependency anyhow`. Дополнительно не
копируются ignored и незакоммиченные данные (`.node`, `fixtures`, `.secrets` и
текущие изменения), без которых нет ни сборки, ни live-проверок. Повторно
рассмотреть, когда нужен параллельный checkout и в нём восстановлен vendor
(`tools/bootstrap.ps1 -RestoreVendor`) с отдельным disposable testnet data root.

### Отказ: computer use

Скриншоты и ввод Slint-окон были бы полезны, но готового бандла под 0.2.1-rc.3 нет
(`dsh-cua-bundle` опубликован только как 0.2.2-alpha.2, ставить чужую alpha в это
дерево нельзя), поэтому монтирование пришлось бы собирать вручную из
`dsh-computer-use` + `dsh-cua` + native-драйвера. Сам пакет экспериментальный и без
promise стабильности, нативный драйвер грузится в процесс хоста (падение native
останавливает хост), нужны desktop-разрешения и графический сеанс, а управление
идёт по общему рабочему столу, где стоит рабочая копия `C:\Flint` с mainnet-данными;
approval в текущем режиме отключён. Физические D-06…D-08 (mixed-DPI, NVDA, IME)
автоматизацией не закрываются. Рабочий аналог для кадров — `read_image` и захват окна
средствами ОС. Повторно — на одноразовой Windows-VM с testnet-пилотом и явным
разрешением пользователя на управление вводом.

### Отказ: browser automation

Конкретного веб-сценария у Flint нет: интерфейс — нативный Slint, Chromium не
проверяет ни окна, ни ДПИ. Повторно — при появлении веб-поставки (например,
документации или веб-формы), отдельно от desktop-приёмки.
