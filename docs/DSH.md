# DSH: инструменты и делегации в этом проекте

Актуализировано: 2026-10-28. Документ описывает, что установлено в профиль DSH
`desktop` и как этим пользоваться следующим сессиям. Профиль и его конфигурация:
`%USERPROFILE%\.dsh\profiles\desktop` (`package.json`, `cordis.patch.yml`); сам
профиль живёт вне репозитория и в `C:\DHW` не копируется.

## Что установлено

Пять официальных бандлов `0.2.1-rc.3`. Все прописаны в `dsh.profile.bundles`,
установка применена перезапуском DSH 2026-10-28.

| Бандл | Инструменты | Состояние проверки |
|---|---|---|
| `dsh-experimental-terminal-bundle` | `terminal_open/send/read/signal/close/list` | **проверено**: `$env:TMP` и PID переживают вызов инструмента |
| `dsh-experimental-session-search` | `session_search`, `session_event_search/read/trace`, `session_trace` | **проверено**: 19 сессий по `Janus`, все с `cwd=C:\DHW` |
| `dsh-experimental-inspector-profile` | вкладка сырых логов сессии и узлов Chat | строки в конфиге есть; в UI глазами не подтверждалось |
| `dsh-experimental-plugin-market-bundle` | `plugin_market`, вкладка Discover | работает, но `indexes: []` — без URL индекса в Settings пусто |
| `dsh-subagent-codex` | `subagent_codex` | **проверено** одним вызовом 2026-10-28 (см. `security/JANUS_REVIEW_2026-10-28.md`) |

## Терминал

Постоянный шелл нужен, чтобы не терять окружение между вызовами: в этом проекте
перед сборкой обязательны `$env:TMP = $env:TEMP = 'C:\DHW\.tmp'` из-за длинных
путей MSVC, и раньше это приходилось повторять в каждой команде.

- Держать открытым только на время работы; закрывать `terminal_close`.
- Ставить TMP один раз после `terminal_open`, дальше пользоваться как обычным шеллом.
- Обычные короткие команды по-прежнему выгоднее выполнять одним `pwsh`: так
  результат чище и не остаётся лишней сессии.
- В выводе PTY видно эхо набранной строки — это нормально, результат идёт отдельной
  строкой.

## Поиск по прошлым сессиям

`session_search` ищет по истории сессий с тем же `cwd`; текущая сессия из выдачи
исключена. Это дешевле, чем перечитывать `docs/`: перед задачей имеет смысл искать
там, где уже что-то решали.

Типичные запросы: имя модуля (`Janus`, `refund_available`), формулировка замечания,
номер пункта. Дальше — `session_event_read`/`session_trace` по конкретному событию.

## Делегации Codex

Разрешены владельцем проекта, лимиты подписки Plus небольшие и **общие** с
приложением Codex.

- Нативный процесс не стартует до первого вызова: простой ничего не стоит.
- Настройки берутся из `~/.codex/config.toml`, а не из DSH. На 2026-10-28 там
  `model = "gpt-5.6-terra"`, `model_reasoning_effort = "high"`,
  `service_tier = "priority"` — дорогая комбинация. Дешёвый вариант для делегаций
  из DSH — закрепить `model` в конфиге бандла (`gpt-6-luna`), но это снимает только
  модель, не effort и не tier.
- При делегации на Windows открывается видимое окно Windows Terminal с
  `codex.exe`: ОС выделяет консоль процессу. Это не канал связи — результат
  приходит через инструмент, — и окно не нужно держать. По завершении процесса
  вкладка может остаться пустой с курсором; её можно закрыть, внутри уже ничего не
  работает. Отдельно в системе постоянно живёт служба
  `CodexSandboxService.OpenAI.Codex` (Automatic): её ставит приложение Codex, к
  делегациям она не привязана и окон не создаёт. Заголовок вкладки с путём к
  `codex.exe` — не изменение `defaultProfile` Windows Terminal: там остаётся
  Windows PowerShell.
- **Находки Codex обязательно проверять по коду.** 2026-10-28 из семи находок одна
  («критичная») оказалась ложной; проверка заняла один тест на 12 строк.
- Где применять: большой read-only разбор (у Codex окно 500k и свои инструменты),
  второе мнение по опасному коду. Не применять: механические правки, прогон тестов,
  веерные параллельные делегации.

## Смысловой поиск и LM Studio

Остался только для запросов «где логика, отвечающая за <смысл>» по-русски; поиск по
идентификаторам дешевле делать грепом, а историю — через `session_search`.

- **`bge-m3` держать выгруженной**, загружать на время запроса: Q8_0 занимает ~9 ГБ
  видеопамяти.
- **`nomic` выгружать обязательно.** LM Studio игнорирует поле `model`, обслуживает
  один эмбеддер за раз; при чужом эмбеддере индекс молча собирается неправильной
  размерности (1024 — `bge-m3`, 768 — `nomic`).
- Индекс в `.tmp\semantic\` устаревает вместе с кодом: на 2026-10-28 он был старше
  семи файлов `crates/`, то есть перед первым поиском всё равно нужен `-Rebuild`
  (~23 с на 83 файлах).

## Что не ставили и почему

- `dsh-experimental-tool-worktree` — в проекте **нет `.git`**, worktree не на чем строить.
- `dsh-subagent-claude-code` — по решению владельца не нужен.
- `dsh-experimental-auto-review` — активируется только под пресетом Auto; при
  текущей политике `approval: never` эффекта не даёт.
- `dsh-experimental-ralph-bundle`, `dsh-experimental-agent-team-profile` — дублируют
  `workflow` и обычных сабагентов.
- `dsh-experimental-voice-input-bundle`, `-badge-skill-bundle`,
  `-session-titles-bundle`, `-cot-translation-bundle` — не относятся к задачам проекта.
