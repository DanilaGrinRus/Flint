# Нода и кошелёк: как это работает сейчас

Короткий ответ: **нода синхронизируется в фоне, пока приложение запущено**, а
кошелёк подключается к ней и не ждёт окончания синхронизации. Но это **не
постоянный демон**: при выходе Flint нода останавливается. Постоянная фоновая
нода — отдельная задача после фазы 5.

## Текущий запуск

1. При старте Flint читает `auto_start_node` (по умолчанию включено).
2. `NodeManager::start` поднимает управляемую `grin` в фоне (`spawn_blocking`),
   поэтому окно и кошелёк открываются, не дожидаясь синхронизации.
3. Кошелёк подключается к ноде на loopback; статус показывает фазу:
   `starting → headers → blocks → ready`.
4. Пока фаза не `ready`, **отправка/скан блокируются** с понятной ошибкой:
   синхронизация не должна приводить к трате по устаревшему tip.
5. При выходе приложения нода останавливается (`NodeManager::Drop` и обработчик
   `ExitRequested`), дочерний процесс не остаётся висеть.

## Подключение к уже запущенной ноде

`NodeManager::start` сначала проверяет публичный порт:

- если там уже отвечает **здоровая нода** с нашим секретом и правильными
  `chain`/`user_agent` — приложение подключается к ней (`is_external() == true`)
  и **не запускает вторую**;
- если порт занят чужим сервисом — ошибка, без тихого запуска второй ноды.

Это же покрывает ручной запуск `tools/run-testnet-node.ps1` и внешнюю ноду:
кошелёк может подключиться к уже синхронизированной.

## Чего ещё нет

- **Постоянной ноды после закрытия Flint.** Нет Windows-сервиса/задания
  автозапуска, нет отдельного daemon-процесса, который живёт без GUI.
- **Автозапуска при входе в систему.** `auto_start_node` — только «вместе с
  приложением».
- **Паузы/ограничения синхронизации**, индикатора трафика/диска, фонового
  обновления `grin.exe`.
- **Отдельного IPC-контроля** фоновой ноды и политики доступа к ней.

## Что потребуется для «нода всегда синхронизируется»

1. **Фоновая служба**: Windows Service или scheduled task от пользователя,
   который поднимает `grin` при входе и держит его после закрытия UI.
2. **Attach-протокол**: кошелёк подключается к уже работающей ноде (уже есть),
   проверяет секрет/сеть/версию; не запускает вторую.
3. **Управление**: start/stop/status/pause, graceful shutdown, автоперезапуск,
   проверка зависания (heartbeat), ограничение диска/трафика.
4. **Безопасность**: owner API только loopback + Basic-auth, ACL на секреты,
   foreign API — только через прокси/onion, никакого `0.0.0.0`.
5. **Данные**: отдельный каталог ноды, независимый от профилей кошелька; миграция
   и обновление бинаря с проверкой версии.
6. **UX**: статус «нода работает в фоне», кнопка «остановить», предупреждение о
   диске, понятное поведение при смене сети.
7. **Гейты**: kill/restart, power-loss, upgrade, две копии не поднимают две ноды,
   mainnet не стартует случайно.

Это отдельный этап (в ROADMAP — «фоновая нода после фазы 5»), а не текущая
функция. До него корректная формулировка: **«нода синхронизируется, пока открыт
Flint; кошелёк подключается к ней без ожидания синхронизации»**.
