# Ответ на внешние ревью 0.1.30 (актуализировано для 0.1.68)

> **HISTORICAL:** документ относится к периоду до удаления Tauri (2026-10-26). Ссылки на `crates/app`/`ui/` и старые `--selftest`/UI-проверки — исторические.


Два разбора: рекомендации «свежим взглядом» (12 пунктов) и независимая
проверка исходников (`FLINT_0.1.30_REVIEW_RU.md`). Ниже — что закрыто, что
остаётся и где я не согласен.

## Закрыто (по версиям)

- **0.1.32** — явный бэкенд без тихого отката; гейт готовности ноды; индекс
  адреса в RPC; локальный режим (0.477 → 0.454, только комиссия).
- **0.1.33** — журнал этапов RPC (`locked` / `finalized_not_posted` / `posted`),
  сверка UUID ответа, идемпотентная финализация, `retry_post` через
 `get_stored_tx`. Живой прогон: крах между подписью и публикацией, повтор в
  новом процессе без второй подписи.
- **0.1.34** — идемпотентный приём: ответ сохраняется до armor, повтор отдаёт тот
  же slatepack, запись живёт до подтверждения.
- **0.1.35** — переключение сети и профиля «на лету», без перезапуска; журналы на
  профиль; RPC-профили в списке.
- **0.1.36** — `address_index` и `pending_scan` в состоянии профиля.
- **0.1.37** — restore в RPC через `create_wallet`, скан без 30-секундного
  обрезания, `validated` в summary.
- **0.1.38** — прогресс скана, быстрый отказ вместо зависания, защита
  summary/activity/pending.
- **0.1.39** — Tor публикует только `POST /v2/foreign` через loopback-прокси;
  owner API закрыт (живая проверка: 403).
- **0.1.40** — зануление ключа сессии, Basic-auth, keychain-токена и секрета
  процесса; ACL на секреты ноды и Tor.
- **0.1.41** — крэш-раннер RPC: границы `send_prepare` и `finalize_tx` пройдены;
  найден и исправлен баг `get_stored_tx` (два аргумента вместо трёх).
- **0.1.42** — `republish` с `fluff` для зависших в пуле сделок.
- **0.1.43** — embedded-хуки и CLI (`init`/`receive`/`scan`) для крэш-теста.
- **0.1.44** — фаза 0.5: секрет owner API создаётся до старта, fail-closed,
  только loopback; живая проверка: 401 без auth, 200 с ним.
- **0.1.45** — embedded-приём шифрует ответ на адрес отправителя (`MODE=1`).
- **0.1.46** — то же для RPC-приёма: sender из armor, ответ шифруется,
  отправитель принимает (`posted`).
- **0.1.47** — embedded-крэш-границы пройдены, продолжение публикует без второй
  подписи; идемпотентность после подтверждения. Auth-развязка: owner закрыт,
  foreign оставлен открытым (read-only, нужен кошелькам).
- **0.1.48** — `live_testnet` переписан под существующие кошельки и готовность
  через `node_info()`; юнит-тесты hex-секрета и записи `node_api_secret_path`.
- **0.1.49** — сверка суммы подтверждённой транзакции с журналом; расхождение
  остаётся `failed_recoverable`, а не удаляется.
- **0.1.50** — пароль и seed-фраза в командах Tauri зануляются (`Zeroizing`).
- **0.1.51** — capability `main` + `freezePrototype`; установщик IExpress (позже удалён);
  минимальная длина пароля 12 (смягчение PBKDF2-100).

## Закрыто в 0.1.52

- **Журнал:** терминальные `confirmed`/`cancelled` архивируются в
 `pending/archive/`, а не удаляются.
- **Доверие к ноде:** `chain`/`user_agent`, пиры обязательны для `ready`,
  подключение к уже запущенной ноде.
- **Парольная политика:** 12 символов, 3 класса до 16, запрет простых слов;
  pending-файлы получают ACL, devtools выключены в release.

## Закрыто в 0.1.53

- **Смена пароля:** встроенный бэкенд и RPC через owner API; политика та же.
- **Удаление кошелька:** каталог переносится в trash/, имя профиля
  подтверждает операцию; RPC — вручную.

## Закрыто в 0.1.54

- **CORS управляемой ноды:** внутренний порт + прокси на публичном,
  Access-Control-* вырезаются, OPTIONS — 403; живьём 401/200/403.

## Закрыто в 0.1.68

- **Tor-мосты:** при блокировке Tor `bridges.txt` добавляет obfs4/snowflake/
  webtunnel и общий `lyrebird.exe` в `torrc`; без lyrebird — понятная ошибка.
  Инструкция: `docs/operations/TOR_BRIDGES.md`.
- **Тестовый мусор удалён:** direct-test-сборки, feature и 3 ГБ кэша; обычный
  релиз больше не содержит test-only веток.

## Закрыто в 0.1.67

- **Адресная книга:** `ContactBook` хранит адрес и понятное имя одним
  ChaCha20-Poly1305-блобом под history-ключом; на диске нет ни адреса, ни
  никнейма. UI: добавить/изменить/удалить, «Написать», имена в истории.
  4 теста крейта.

## Закрыто в 0.1.66

- **Офлайн-relay:** `flint-relay` без кошелька, TTL/квоты/диск; store переживает
  перезапуск. Развёртывание через Tor описано в `docs/operations/RELAY.md`.
- **Ack:** подпись получателя, привязанная к `to`, `id` и `ts` (±5 минут).
  Старый `{to}` принимается только локальным gateway; публичный relay — 401.
- **Мессенджер:** исправлено ложное «Кошелёк заблокирован» на RPC
  (`messenger_seed` читал не тот JSON); ошибка теперь видна в UI.
- **Портативность RPC:** `grin-wallet.toml` перезаписывается под фактический
  каталог; тестовые сборки переживают перенос папки.

## Закрыто в 0.1.65

- **Прямой onion:** `TorListener` публикует gateway как hidden service (платежи
  и сообщения на одном onion, owner API закрыт); `DirectOnionTransport`
  доставляет на onion получателя без relay. Живой обмен двух кошельков через
  реальный Tor: 40,77 с; путь `TorListener` → gateway: 37,54 с.
- **Gateway под Tor:** принятый сокет переводится в blocking; иначе запрос,
  разбитый на два пакета, закрывался без ответа. Регрессионный тест добавлен.
- **UI:** пустой relay при активном Tor = прямой режим; экран показывает
  «Прямая доставка по Tor».

## Закрыто в 0.1.64

- **Onion-транспорт:** GatewayTransport::with_socks (SOCKS5) для .onion;

## Остаётся (принято, приоритет сверху)

1. **Мессенджер.** Прямой onion, relay, подписи, квоты и signed ack закрыты
   (0.1.65/0.1.66). Осталось: публичный relay/PoW и rate limit,
   forward secrecy/ratchet, push и группы.
2. **Фаза 2 (остаток).** `chain`/`user_agent`, пиры для `ready`, свежесть tip,
   отмена RPC-скана и кооперативная отмена embedded-скана между батчами
   сделаны; живой endpoint-switch, graceful stop и реальный Tor
   bootstrap/остановка проверены. Осталось: живой прогон с реальным
   mainnet-кошельком/сетью.
3. **CORS вне прокси.** Управляемая нода закрыта прокси (0.1.54); прямой режим,
   внешний `node_url` и ручной запуск на 13413 идут мимо прокси.
4. **PBKDF2-100 / Argon2id.** Argon2id-конверт seed реализован для обоих
   бэкендов, миграция legacy и mainnet-гейт — 0.1.69; остались внешний аудит,
   живой прогон и обрыв питания. Ключ истории также переведён на Argon2id v2 и
   профильный файл.
5. **UI-долги (остаток).** Смена пароля и удаление кошелька сделаны для
   встроенного бэкенда; RPC-удаление теперь доступно из UI (stop + trash). Pending-файлы получили ACL, но
   остаются открытым JSON.
6. **Права IPC для собственных команд.** В Tauri 2 capability-файл их не
   ограничивает; devtools выключены в release, защита — CSP и одно окно.
7. **Live-тесты вручную.** `tools/run-live-suite.ps1` готов, сценарий прогнан;
   CI-провайдера в проекте нет.
## Где не согласен

- `base64 0.13` — штатный API выбранной версии; менять отдельно от обновления
  зависимости смысла нет.
- «Нет предупреждения о перезапуске» — переключение теперь не требует
  перезапуска, кошелёк честно блокируется и просит пароль.
- «Серая кнопка без причины» — `title` и статус фазы есть.

## Порядок работ

1. Мессенджер: публичный relay/PoW, forward secrecy; прямой onion и signed ack готовы.
2. Фаза 2: личность и свежесть ноды, подключение к запущенной ноде.
3. Argon2id-конверт seed (фаза 3) — сделан; дальше внешний аудит и живой прогон.
4. UI: смена пароля, удаление кошелька, закрытый pending.
