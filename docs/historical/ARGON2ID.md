# Argon2id-конверт seed — дизайн и тест-план (фаза 3)

> Исторический дизайн/аудит. Tauri удалён 2026-10-26; ссылки на `crates/app`
> и `--selftest` относятся к прежней оболочке. Актуальный код —
> `crates/runtime/src/seed.rs`, проверка — `flint-selftest`/`tools/ci.ps1`.

**Статус: срезы 1–5 реализованы в рабочем дереве (0.1.69, без релиза).**
Версия не менялась, артефакты `dist/` собраны до этих изменений. Сделаны конверт
для новых кошельков, RPC-бэкенд, mainnet-гейт, миграция legacy по кнопке,
kill-дрилл по точкам M0–M5 и Argon2id для ключа истории мессенджера. Остались
внешнее человеческое ревью, живой прогон миграции с синхронизированной нодой и
обрыв питания на VM; см. раздел 13.

Рамки: testnet; реальные средства по-прежнему запрещены. Документ отвечает на
четыре вопроса: где именно seed читается и пишется, как устроен PBKDF2 сейчас,

проверять. Дизайн остаётся источником истины для ещё не сделанных срезов.

Вывод, на котором держится весь дизайн: **у upstream нет API, принимающего seed
напрямую.** Единственный вход — «пароль + файл по фиксированному пути». Поэтому
любая защита сильнее PBKDF2-100 требует, чтобы пароль, который видит upstream,
имел высокую энтропию, а настоящий секрет лежал в отдельном конверте.

Типы `WalletSeed`/`EncryptedWalletSeed` приватны, значит Flint реализует
legacy-формат сам (PBKDF2-SHA512-100 + ChaCha20-Poly1305 + JSON) и сверяет его с
upstream тестами в обе стороны (раздел 8, тесты 7–8).

## 2. Почему это блокер mainnet

100 итераций PBKDF2 — не растяжение ключа, а его отсутствие: одна проверка
пароля стоит микросекунды, на одном ядре CPU это десятки тысяч попыток в секунду,
на GPU — на порядки больше. Парольная политика (12 символов, 3 класса, запрет
`password`/`qwerty`/`123456`, `crates/core/src/service.rs:1701`) сужает перебор,
но не делает человеческий пароль 256-битным. Кто получил копию каталога
(`wallet.seed`), перебирает его офлайн.

Argon2id с `m = 64 МиБ, t = 3, p = 4` (вторая рекомендация RFC 9106) стоит
~0,3–0,6 с и 64 МиБ на попытку; память доминирует, поэтому GPU-перебор дорожает
на 3–5 порядков. Это и есть смысл фазы 3.

## 3. Конфликт с правилом «не перезаписывать wallet.seed»

Правило понимается буквально: существующий seed-файл **не переписывается новым
содержимым и не регенерируется**. Из него следует два ограничения:

1. Нельзя вызывать upstream `change_password` для перевода кошелька на Argon2id:
   он физически перезаписывает `wallet.seed` (`default.rs:315-365`).
2. Нельзя оставлять на диске слабый файл после миграции: иначе Argon2id
   защищает только копию, а старый блоб с PBKDF2-100 остаётся взламываемым, и
   смысла в конверте нет.

Отсюда дизайн: **seed-файл перестаёт быть источником истины.** Источник истины —
конверт `wallet.seed.v2`. Оригинальные байты `wallet.seed` при миграции
сохраняются **внутри** конверта (поле `legacy`), а сам путь `wallet.seed`
используется только как временный артефакт на время разблокировки — с паролем из
256 случайных бит, который живёт в памяти и нигде не сохраняется. Такой файл
бесполезен для атакующего даже если остался после краха.

Явно: при миграции `wallet.seed` **удаляется** после проверки конверта и адреса.
Это не перезапись, а перенос содержимого под Argon2id с возможностью побайтового
отката, пока пароль не менялся (раздел 6; после смены пароля откат
переупаковывает seed под текущий пароль). Если это неприемлемо, есть срез 3a без
миграции: старые кошельки не трогаются вообще (раздел 4, вариант C).

## 4. Варианты и решение

| # | Вариант | Плюсы | Минусы |
|---|---|---|---|
| A | Перешифровать seed под случайный ключ (upstream `change_password`) + Argon2id-конверт с ключом | минимум нового кода | перезаписывает `wallet.seed` — нарушает правило; окно `.bak` после краха |
| B | Конверт — источник истины; legacy-байты внутри; временный seed с random-паролем | правило соблюдено по существу; работает одинаково для обоих бэкендов; откат | временный файл в пути `wallet.seed`; несовместимость с официальным `grin-wallet` |
| C | Только новые кошельки на конверте, legacy не трогаем | нулевой риск для существующих; строго буквальное соблюдение правила | старые кошельки остаются на PBKDF2-100 навсегда |

**Решение: C → B по срезам.** Сначала 3a (новые кошельки сразу на Argon2id,
legacy-кошельки работают как раньше и получают предупреждение в UI). Затем 3b —
явная миграция по кнопке, с подтверждением пароля, проверкой и откатом. Mainnet
без конверта не открывается (гейт), поэтому «навсегда» вариант C не становится
разрешением для реальных денег.

## 5. Конверт `wallet.seed.v2`

Файл: `<wallet_home>/wallet_data/wallet.seed.v2`, JSON, UTF-8, не больше 64 КиБ,
owner-only ACL (`crates/core/src/win_acl.rs`). Если ACL применить не удалось,
запись seed отклоняется: файл не остаётся с широким доступом.

```json
{
  "format": "flint-seed",
  "version": 1,
  "network": "testnet",
  "kdf": { "algorithm": "argon2id", "version": 19, "m_kib": 65536, "t": 3, "p": 4,
           "salt": "<base64 16 байт>" },
  "cipher": { "algorithm": "chacha20poly1305", "nonce": "<base64 12 байт>" },
  "seed_len": 32,   // 16/20/24/28/32 — столько, сколько дала фраза
  "address": "tgrin1…",
  "ciphertext": "<base64>"
}
```

- **AAD** (байты, порядок фиксирован): `b"flint-seed-v1\x00"` ++ network UTF-8 ++
  `\x00` ++ `m_kib`, `t`, `p`, `19` как `u32 LE` ++ salt(16) ++ nonce(12) ++
  `seed_len` как `u32 LE` ++ address UTF-8. Эти поля связаны тегом. Строки
  `format`, `kdf.algorithm`, `cipher.algorithm` и top-level `version` в AAD не
  входят — их проверяет `validate()` до расшифровки; менять их без новой версии
  формата нельзя.
- **Plaintext**: JSON `{"seed":"<base64>","legacy":"<base64, опционально>"}`.
  `seed` — энтропия Grin (16–32 байта), не мнемоника; длина обязана совпадать с
  `seed_len`. `legacy` — точные байты старого `wallet.seed` (только у
  мигрированных кошельков; для отката). Побайтовый откат возможен, пока пароль
  не менялся; после смены пароля seed переупаковывается под текущий.
- **Параметры**: `m=65536`, `t=3`, `p=4`, выход 32 байта. При чтении допустимы
  `19456 ≤ m ≤ 262144`, `1 ≤ t ≤ 10`, `1 ≤ p ≤ 8`, всё остальное — отказ до
  выделения памяти (защита от случайного/злонамеренного файла).
- **Случайность**: `ring::rand::SystemRandom` (уже зависимость). Nonce и соль
  новые на каждую запись.
- **Пароль**: байты UTF-8 как введены, без нормализации (upstream тоже не
  нормализует; нормализация сломала бы совместимость при смене версии).
  Держится в `Zeroizing`.
- **Ошибки**: неверный пароль и повреждённый шифротекст дают одну ошибку
  «неверный пароль или повреждённый файл»; структурные ошибки (JSON, base64,
  размер) отличаются, но возникают до KDF и не являются оракулом пароля.
  Чужой/уже лежавший конверт автоматически не удаляется; исключение — конверт,
  который эта же запись создала и не смогла проверить: он убирается или
  восстанавливается прежний файл, чтобы не заслонить целый seed.
- **Адрес**: адрес индекса 0, проверяется после открытия через бэкенд. Хранится
  в открытом виде (он и так не секрет) и входит в AAD.

## 6. Потоки

### 6.1 Новый кошелёк (обе ветки — 3a)

1. Энтропия 32 байта из `SystemRandom` → мнемоника (`grin_keychain::mnemonic`).
2. Конверт строится и пишется первым: tmp → fsync файла → rename. На Windows
   rename идёт через `MoveFileExW(MOVEFILE_WRITE_THROUGH)` (FlushFileBuffers на
   каталоге там недоступен), на Unix после rename вызывается fsync каталога.
   Удаления файлов не fsync-ятся: обрыв питания остаётся отдельным ручным
   прогоном. Читается обратно и расшифровывается — сверка энтропии.
3. Upstream создаёт кошелёк **из этой мнемоники** с паролем `K` (64 hex-символа
   из `SystemRandom`): embedded — `create_wallet(mnemonic, K)`, RPC —
   `create_wallet` (создание RPC-кошелька в UI пока не поддерживается, меняется
   только восстановление).
4. Открытие с `K`, проверка адреса против конверта, удаление `wallet.seed`.
5. Мнемоника показывается пользователю один раз, как и сейчас
   (`crates/core/src/service.rs:345`).

Побочный эффект шага 3: `create_wallet` с фразой ставит init-статус
`InitNeedsScanning` (`default.rs:220-223`), то есть новый пустой кошелёк покажет
«нужен скан». Либо принимаем (скан пустого кошелька короткий), либо снимаем
статус, если upstream даёт для этого API, — решает спайк S1. Альтернатива без
побочного эффекта — `create_wallet(None)` и конверт вторым шагом, но тогда
обрыв между шагами оставляет seed с неизвестным `K`; такой каталог помечается
маркером «незавершённое создание» и требует явного действия пользователя.

Крах на шаге 3–4: конверт уже есть, база может отсутствовать. При следующей
разблокировке конверт расшифровывается, из энтропии получается мнемоника и
кошелёк до-создаётся (`create_wallet`/`recover`) — пользователь вводит только
пароль. Это надо подтвердить спайком S1 (раздел 7).

### 6.2 Восстановление из фразы

Фраза → энтропия → конверт (шаг 1–2 выше) → upstream создаёт кошелёк из фразы с
`K` → проверка адреса → удаление `wallet.seed`. Отличие от 6.1 только источником
энтропии. Сбой после записи конверта восстанавливается тем же до-созданием.

### 6.3 Разблокировка (конверт есть)

1. Прочитать конверт, Argon2id(пароль) → ключ, AEAD-open → энтропия.
2. Сгенерировать `K`, записать `wallet.seed` в legacy-формате (PBKDF2-100 +
   ChaCha20-Poly1305) с ACL, атомарно.
3. RPC: процесс уже запущен без seed (снимается проверка `rpc_backend.rs:101`);
   вызвать `open_wallet(K)`. Embedded: `unlock_with(..., K)`.
4. Сверить адрес индекса 0 с конвертом. Не совпал — заблокировать, удалить
   временный файл, вернуть ошибку. Совпал — удалить `wallet.seed`.
5. В памяти остаются только `K` (до конца операции) и объект кошелька; энтропия
   зануляется (`Zeroizing`).

Если до разблокировки на диске уже лежал `wallet.seed` (обрыв миграции или
чужой файл), его байты читаются в память **до** записи временного файла и
возвращаются на место, если адрес не совпал. Удаляются только после успешной
проверки адреса — временный файл и оставшиеся слабые `wallet.seed.bak*`.
Перед этим конверт сверяется с сетью профиля: конверт другой сети отвергается
до записи временного seed.

### 6.4 Блокировка и выход

`lock`/exit закрывают бэкенд, удаляют `wallet.seed`, зануляют `K`. Остаточный
файл после краха безопасен (пароль неизвестен) и удаляется при следующей
успешной разблокировке.

### 6.5 Смена пароля

Только переупаковка конверта: старый пароль → энтропия → новый пароль, новая
соль и nonce, атомарная замена, проверка чтением. Upstream `change_password` не
вызывается вообще, `wallet.seed` не появляется. История мессенджера
переворачивается существующим `rewrap` (`crates/messenger/src/keywrap.rs`).
Для legacy-кошелька поведение прежнее (upstream `change_password`) + предложение
миграции.

### 6.6 Миграция legacy → конверт (3b, только по кнопке)

Предусловия: кошелёк заблокирован, `wallet.seed` есть, конверта нет.

| Шаг | Действие | Крах на этом шаге |
|---|---|---|
| M0 | Пароль → расшифровать legacy-файл, получить энтропию; адрес `m/0/1/0` выводится офлайн | ничего не изменено |
| M1 | Конверт с `legacy`-байтами: tmp → fsync → rename → fsync каталога; `write_envelope` сразу читает и расшифровывает файл | `wallet.seed` цел, `.v2.tmp` удаляется при старте/повторе |
| M2 | Независимое чтение конверта, расшифровка, сверка энтропии | при ошибке конверт удаляется, `wallet.seed` цел |
| M3 | Удаление слабых копий `wallet.seed.bak*` — **до** удаления seed | оба файла, но слабых копий уже нет; следующая разблокировка удалит seed |
| M4 | Удалить `wallet.seed` | конверт авторитетен, слабых файлов нет; разблокировка идемпотентна |
| M5 | Вернуть результат; лог приложения без секретов | идемпотентно |

Адрес для конверта не читается из базы и не требует узла: он выводится из
энтропии тем же путём `m/0/1/0`, что и у upstream. Но приложение перед миграцией
всё равно открывает legacy-кошелёк паролем и сверяет его адрес индекса 0 с
выведенным: если база принадлежит другому seed, миграция отказывает до записи и
`wallet.seed` не трогает. Сам `SeedStore::migrate_legacy` этого не делает — у
него нет открытого кошелька; это ответственность команды `wallet_migrate_seed`.
M2 сверяет энтропию с энтропией, записанной в конверт; адрес к этому моменту уже
сверен с реально открытым кошельком в команде (до M1), а не выводится повторно.

Перед M0 проверяются `wallet.seed.bak*` — наследие неудачных смен пароля
(`seed.rs:124-143`). Это такие же слабые копии seed: миграция предупреждает о них
и требует удалить их с подтверждением, иначе после включения Argon2id на диске
останется взламываемый PBKDF2-100-блоб. Удаление перенесено в M3 (раньше оно шло
после M4), поэтому ни одна точка обрыва не оставляет слабую копию рядом с уже
готовым конвертом. Если копию удалить не удалось, миграция удаляет конверт и
оставляет `wallet.seed` как был. Согласие фиксируется маркером
`.wallet.seed.bak.cleanup`; после обрыва M3 следующая успешная разблокировка
конверта дочищает оставшиеся `wallet.seed.bak*` по этому маркеру. Без маркера
(пользователь не давал согласия) разблокировка копии не трогает.

Откат в любой момент до M4: удалить конверт (seed цел). После M4: кнопка
«Отключить Argon2id» — расшифровать конверт и записать `wallet.seed`. Если
пароль не менялся с момента миграции, возвращаются **точные исходные байты** из
поля `legacy` (они всё ещё открываются этим паролем); после смены пароля
исходный блоб уже не подходит, поэтому seed переупаковывается в legacy-формате
под текущим паролем. В обоих случаях запись проверяется чтением, и только потом
удаляется конверт.
Это осознанный downgrade с предупреждением; нужен для совместимости с
официальным `grin-wallet`. На mainnet откат запрещён: гейт §6.7 сделал бы
кошелёк неоткрываемым. Проверка стоит и в IPC-команде, и в самом
`SeedStore::disable_envelope`, поэтому обойти её прямым вызовом нельзя;
UI не показывает кнопку. Если удаление конверта в конце отката не удалось,
записанный `wallet.seed` удаляется, а рабочий конверт остаётся: операция
возвращает ошибку и ничего не ослабляет.

### 6.7 Mainnet-гейт

`network == mainnet` и конверта нет → отказ в разблокировке с текстом
«кошелёк не защищён Argon2id; включите защиту seed или создайте новый кошелёк».
Testnet legacy открывается с предупреждением. Гейт проверяется тестом без
реальных средств.

### 6.8 Аварийный ремонт «конверт не открывается, wallet.seed цел»

Состояние E+S может остаться после отказа удаления конверта или порчи `.v2`.
`SeedStore::quarantine_unreadable_envelope(password)`:

1. требует `kind()==Envelope` и наличие `wallet.seed`;
2. если конверт открывается этим паролем — отказывает (ремонт не нужен);
3. расшифровывает `wallet.seed` тем же паролем (неверный — ничего не меняет);
4. переименовывает конверт в `wallet.seed.v2.broken-<pid>-<nanos>` (не удаляет);
5. `wallet.seed` остаётся на месте, `kind()` становится `Legacy`.

Команда `wallet_repair_envelope` сериализована с остальными seed-операциями;
кнопка «Восстановить из wallet.seed» есть в баннере незавершённой миграции на
locked-экране и экране кошелька (диалог сам блокирует кошелёк). Если конверт
читается, но кошелёк не открывается (адрес/база), в диалоге есть явный флаг
«вернуть wallet.seed из конверта»: `restore_legacy_from_envelope` записывает
seed (точные байты, если пароль не менялся, иначе переупаковку), проверяет
чтением и **переименовывает** конверт в `.broken`, не удаляя его. После ремонта
пользователь снова видит баннер миграции и может включить Argon2id заново.
На mainnet ремонт разрешён как аварийный (данные сохраняются), но открыть
legacy-кошелёк до повторной миграции гейт не даст — это осознанно.

Если конверт читается, но адрес не совпадает с базой, ремонт не поможет;
`disable_envelope` (testnet) вернёт `wallet.seed` из энтропии, после чего
кошелёк можно открыть официальным `grin-wallet` или восстановить из фразы.

## 11. Что этот дизайн не защищает

- Malware/кейлоггер при разблокированном кошельке: пароль и энтропия в памяти.
- Подмену приложения или его бинарника.
- Атакующего с правом записи в каталог: он может подменить конверт целиком
  (откат к своей версии), но не прочитает чужой seed. Целостность против
  активного противника требует внешнего состояния — вне рамок фазы 3.
- Потерю конверта: восстанавливаться надо из фразы, как и раньше; конверт —
  не бэкап.
- Совместимость с официальным `grin-wallet`: после 3b каталог открывается
  только Flint; выход — «Отключить Argon2id» (6.6) или восстановление из фразы.
  Это уже верно для новых кошельков из 3a.

## 12. Решения по открытым вопросам

1. Имя файла — `wallet.seed.v2` (константа `ENVELOPE_FILE`).
2. Параметры — фиксированные `64 МиБ / t=3 / p=4` (`KdfCost::SECURE`); при чтении
   допустимо 19 МиБ–256 МиБ, `t ≤ 10`, `p ≤ 8`. Калибровки нет, чтобы тест-векторы
   оставались воспроизводимыми.
3. Конверт для новых кошельков включён по умолчанию, без настройки.
4. UI для legacy-кошельков — баннер «Seed защищён старым форматом (PBKDF2-100)» с
   кнопкой «Включить Argon2id» на экране кошелька и на карточке блокировки
   (миграция требует заблокированного кошелька); откат «Отключить Argon2id» —
   в настройках, только testnet.
5. Сетевой шаг выполнен: `argon2 0.5.3` и `blake2-rfc` в `vendor/`, сборка снова
   офлайн.

## 13. Состояние реализации (рабочее дерево, 0.1.69 без релиза)

Новые файлы:

| Файл | Что делает |
|---|---|
| `crates/core/src/seed/legacy.rs` | формат upstream `wallet.seed` (PBKDF2-SHA512-100 + ChaCha20-Poly1305 + JSON), чтение и атомарная запись |
| `crates/core/src/seed/envelope.rs` | `wallet.seed.v2`: Argon2id → ChaCha20-Poly1305, AAD на все поля заголовка, лимиты параметров и размера файла |
| `crates/core/src/seed/store.rs` | правила: конверт главнее; временный seed с random-паролем; откат к прежним байтам; смена пароля только переупаковкой |
| `crates/core/src/address.rs` | `address_from_entropy`: адрес `m/0/1/0` из энтропии офлайн, как у upstream |
| `crates/core/tests/migration_crash.rs` | kill-дрилл: дочерний процесс абится в M0–M5 (фича `crash-injection`, только тесты) |
| `crates/messenger/src/keywrap.rs` | ключ истории: v2 Argon2id, чтение v1 PBKDF2, автопереупаковка (срез 5) |

Что теперь происходит в встроенном бэкенде:

- `create_wallet` и `restore_wallet` пишут конверт **до** создания кошелька
  upstream; upstream получает случайный пароль, после проверки адреса
  `wallet.seed` удаляется. В покое seed-файла нет.
- `open_wallet` для конверта материализует временный seed, открывает upstream,
  сверяет адрес и удаляет файл; при любой ошибке возвращает прежнее состояние.
- `lock` удаляет временный файл, если он остался.
- `change_password` переупаковывает конверт (новая соль/nonce), upstream не
  вызывается.
- Кошелёк без конверта открывается ровно как раньше: пароль идёт в upstream,
  `wallet.seed` не трогается. Это и есть 3a без миграции.
- `initialized`, список профилей и `address` учитывают конверт.

В RPC-бэкенде (`grin-wallet` отдельным процессом, 0.1.69):

- процесс стартует, когда на диске есть конверт **или** legacy seed; в покое
  `wallet.seed` нет (спайк S4, `tests/wallet_rpc_seedless.rs`);
- `RpcBackend::open_with_envelope` повторяет путь встроенного бэкенда:
  `prepare_unlock` → `open_wallet(K)` → сверка адреса индекса 0 → `commit_unlock`;
- `restore` пишет конверт до `create_wallet`, upstream создаёт кошелёк под
  случайным паролем, после сверки адреса seed удаляется;
- `change_password` для конверта переупаковывает только конверт, upstream не
  вызывается; `wallet_cli` идёт через `SeedStore`.

Миграция (3b, 0.1.69) — `SeedStore::migrate_legacy` по шагам §6.6, с отказом при
наличии `wallet.seed.bak*`, удалением копий до seed и с откатом
`disable_envelope`. Mainnet-гейт (`ensure_mainnet_ready`) стоит в обоих
бэкендах; `disable_envelope` сам отказывает на mainnet. Ошибка после M1 удаляет
непроверенный конверт, чтобы он не заслонил целый `wallet.seed`.

Крэш-дрилл: `crates/core/tests/migration_crash.rs` запускает миграцию в дочернем
процессе и убивает его (`abort`) в M0–M5; для каждой точки проверяются файлы на
диске, отсутствие слабых копий, разблокировка или повтор миграции, тот же seed и
адрес, затем откат. Ручной обрыв питания остаётся отдельным прогоном.

Ревью: два адверсариальных прохода в изолированном контексте, отчёт и
исправления — [REVIEW_MIGRATION.md](REVIEW_MIGRATION.md). Это не внешний
человеческий аудит; для mainnet он по-прежнему обязателен.

Ключ истории (срез 5, `crates/messenger/src/keywrap.rs`): Argon2id
64 МиБ/t=3/p=4 → ChaCha20-Poly1305, версия 2; старые v1 (PBKDF2-100k) читаются и
после успешной разблокировки автоматически переупаковываются в v2. Обёртка
профильная (`<root>/messenger/history/<network>/<profile>/.history.key`), старый
общий ключ мигрируется при первом открытии; смена пароля идёт через
`.history.key.next` и восстанавливается после обрыва. Приложение пишет обёртку
атомарно (tmp → fsync → rename → проверка чтением), при смене пароля — только
`rewrap`.

Проверено тестами: юнит-тесты кодека и конверта (включая вектор Argon2id из
эталонной реализации), кросс-тесты с upstream (upstream открывает наш
legacy-файл; конверт хранит энтропию фразы), спайк S1, живые тесты RPC с
`grin-wallet.exe` (открытие из конверта, неверный пароль, restore-путь),
миграция, ремонт и откат (юнит-тесты `seed::store`, включая exact-откат,
согласие на копии, сеть, mainnet-запрет и repair), kill-дрилл M0–M5 и 8 тестов
keywrap v2/v1. Полный прогон — в `docs/status/STATUS.md`.

Чего нет:

- обрыва питания на VM: kill процесса автоматизирован, но потеря питания и
  поведение кэша диска — отдельный ручной прогон перед снятием гейта;
- координации с внешним `grin-wallet`: `seed_op` сериализует команды внутри
  процесса, `.flint-seed.lock` — миграцию/откат между процессами Flint, но
  сторонний процесс этот lock не читает;
- внешнего человеческого ревью миграции, которого требует гейт фазы 3
  (адверсариальные проходы в изолированном контексте его не заменяют).

**Гейт фазы 3 остаётся открытым** до закрытия R1/R2 и внешнего аудита; зелёный
`cargo test` сам по себе гейт не закрывает.
