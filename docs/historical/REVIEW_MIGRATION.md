# Адверсариальное ревью миграции seed → Argon2id

> **HISTORICAL:** документ относится к периоду до удаления Tauri (2026-10-26). Ссылки на `crates/app`/`ui/` и старые `--selftest`/UI-проверки — исторические.


**Статус: проведено; гейт фазы 3 этим документом не закрывается.** Это отчёт о
двух независимых проходах по коду и документам, а не внешний человеческий аудит.
Дата: 2026-10-25, рабочее дерево 0.1.69 (без релиза).

## 1. Метод и границы

- Два прохода в изолированном контексте, без общего контекста с основным агентом:
  (A) жизненный цикл миграции, откат, обрывы, UI/команды; (B) криптография
  конверта, legacy-кодек, AAD, лимиты, зануление.
- Рецензенты только читали код и документы, `cargo` не запускали. Полные отчёты
  лежали в `.tmp/review-migration-lifecycle.md` и
  `.tmp/review-migration-crypto.md` (вне поставки).
- Исходное дерево менялось во время ревью. Ниже — состояния находок после
  исправлений; окончательные хеши файлов — в §6. Гейт нельзя закрывать на
  движущемся дереве: перед снятием повторить проход на зафиксированных хешах.
- Модель угроз: локальный атакующий с копией каталога (офлайн-перебор), обрыв
  процесса/питания в любой точке, повреждение файлов, ошибки I/O, две сессии
  одного пользователя. Защита от malware/кейлоггера и подмены бинарника не
  входит (docs/history/ARGON2ID.md §11).

## 2. Вердикты по инвариантам (после исправлений)

| # | Инвариант | Вердикт |
|---|---|---|
| 1 | После успешной миграции нет PBKDF2-100 блобов, включая `.bak*` | **Выполнен для штатного пути и kill M0–M5.** Остаточный риск: обрыв питания между M3 и M4 оставляет `wallet.seed` до следующей разблокировки; удаления не fsync-ятся. |
| 2 | Любой обрыв: следующий запуск открывает тот же кошелёк/адрес | **Выполнен для kill M0–M5.** Остаточный риск: потеря питания/кэш диска, ошибки I/O после rename, отсутствие межпроцессной блокировки. |
| 3 | Неверный пароль/повреждение не меняют состояние | **Выполнен.** Структурные ошибки отличаются от AEAD-ошибки, но до KDF и без оракула пароля. |
| 4 | Нет состояния «UI считает Argon2id включённым, открыть нельзя» | **Выполнен для E+S и читаемого E:** ремонт `wallet_repair_envelope` (quarantine нечитаемого или restore из читаемого с явным флагом). Остаточное: на mainnet legacy после ремонта не откроется до повторной миграции — осознанно. |
| 5 | Seed не удаляется до записи/чтения/расшифровки конверта | **Выполнен.** M4 после M1/M2; перед M4 приложение сверяет адрес реально открытого кошелька с адресом из seed. |
| 6 | Повтор и параллель не разрушают данные | **Выполнен внутри процесса** (`seed_op`, compare-and-delete, repair). Межпроцессная блокировка отсутствует — остаточный риск. |

## 3. Находки и решения

### Закрыто

| Находка | Решение | Проверка |
|---|---|---|
| Cleanup после M1/M2 удалял конверт по пути без сверки | M2/M3/M4 удаляют только байты, записанные этим вызовом; M1 сохраняет валидный конверт, удаляет только неоткрываемый | `remove_envelope_if_unchanged`, crash-дрилл |
| Lock/exit удалял любой `wallet.seed` при наличии `.v2` | Временный seed помечается sidecar `.wallet.seed.transient`; без маркера не удаляется | `lock_does_not_delete_an_unmarked_legacy_seed` |
| Слабые `.bak*` удалялись после seed → crash оставлял слабую копию | Удаление перенесено до seed; согласие фиксируется `.wallet.seed.bak.cleanup`, разблокировка дочищает только по маркеру | `migration_needs_consent_for_backup_copies`, `unlock_without_consent_keeps_weak_backups` |
| Ошибка после M1/M2 могла оставить неоткрываемый конверт, заслоняющий seed | `write_envelope`/`change_password` проверяют и откатывают прежний файл; migration cleanup guarded | `change_password_rewraps_the_envelope_only`, `empty_legacy_blob_is_refused_at_seal_time` |
| M4 при отказе удаления seed оставлял активный конверт и слабый seed | Конверт откатывается в legacy-состояние, если seed остался | crash-дрилл, unit-тесты |
| `disable_envelope` при отказе удаления конверта оставлял PBKDF2-блоб | Записанный seed удаляется, рабочий конверт остаётся | `rollback_writes_the_legacy_seed_back` |
| Нет ремонта «конверт не открывается, seed цел» | `quarantine_unreadable_envelope` переименовывает `.v2` в `.broken`, seed остаётся; `restore_legacy_from_envelope` для читаемого конверта | `unreadable_envelope_is_quarantined_and_legacy_seed_stays`, `readable_envelope_can_be_quarantined_and_materialized_as_legacy` |
| Legacy-байты внутри конверта не использовались | `disable`/`restore` пишут точные байты, пока пароль не менялся; после смены — переупаковка | `rollback_without_password_change_is_byte_exact` |
| Mainnet-откат можно было обойти мимо IPC | Проверка перенесена в `SeedStore::disable_envelope` | `mainnet_refuses_to_disable_the_envelope` |
| Seed удалялся без сверки адреса с реально открытым кошельком | Команда миграции сначала открывает legacy-кошелёк (embedded/RPC), сравнивает адрес индекса 0 с выведенным из seed и при расхождении отказывает до M1 | код + ревью (приложение) |

Сверка адреса живёт в команде `wallet_migrate_seed`: `SeedStore` не умеет
открывать кошелёк. Прямой вызов `SeedStore::migrate_legacy` из другого кода
(CLI/тесты) этой проверки не делает — это ответственность вызывающего.
| Конверт другой сети открывался | `prepare_unlock` сверяет `envelope.network()` с профилем до записи seed | `envelope_from_another_network_is_refused_before_writing` |
| RPC-статус/список профилей не видели `.v2` | Используется `wallet_data_has_seed` (seed или envelope) | `rpc_profiles_are_listed_from_their_own_directories` |
| RPC `wallet_open` сбрасывал `needs_scan` у пересозданной базы | `RpcBackend::needs_scan()` учитывается | код + ревью |
| Seed-команды могли пересекаться | `seed_op` (tokio mutex) вокруг init/open/restore/lock/switch/change-password/migrate/disable/repair/delete | код + ревью |
| ACL ошибка игнорировалась | `write_bytes_atomic` отказывает запись seed без owner-only ACL; пустой `USERNAME` — ошибка | seed-тесты, ревью |
| Паника на коротком nonce в keywrap | Длина nonce проверяется до `copy_from_slice` | `short_nonce_is_an_error_not_a_panic` |
| `fs::read` legacy/previous seed без лимита | `LegacySeed::read_raw` с лимитом 64 КиБ используется в миграции и unlock | `legacy_file_round_trip_and_removal`, ревью |
| `PlainSeed` не занулялся | `Drop for PlainSeed`, decrypted buffer зануляется и на ошибке JSON | ревью + тесты |

### Остаётся (не блокирует текущий testnet, блокирует mainnet-гейт)

| # | Находка | Почему оставлено |
|---|---|---|
| R1 | Нет межпроцессной блокировки каталога: две сессии или внешний `grin-wallet` | `seed_op` держит только внутри процесса; compare-and-delete сужает окно. Нужен файловый lock/именованный mutex. |
| R2 | Удаления `wallet.seed`/`.bak*`/`.broken` не fsync-ятся; power-loss не моделируется | Windows rename durable (`MOVEFILE_WRITE_THROUGH`), но flush каталога для удалений недоступен; нужен ручной прогон на VM. |
| R3 | AAD не связывает строки `format`, `kdf.algorithm`, `cipher.algorithm`, top-level `version` | Их отвергает `validate()` до расшифровки; менять AAD сейчас — ломать формат без новой версии. Defense-in-depth. |
| R4 | `SeedEnvelope::read` проверяет metadata, затем читает; TOCTOU/symlink при праве записи в каталог | Активный локальный писатель уже вне модели §11; можно ужесточить open-by-handle. |
| R5 | Проверка адреса в конверте слабая (префикс/ASCII, не bech32) | В production адрес всегда выводится `address_from_entropy`; `commit_unlock` сравнивает с реальным. Ошибка в API-адресе fail-closed. |
| R6 | `.bak*` после успешной разблокировки удаляются без отдельного диалога (но только по маркеру согласия миграции) | Согласие фиксируется при миграции; без маркера копии не трогаются. UI показывает их количество. |
| R7 | Слабый legacy-пароль не проверяется при миграции | Argon2id замедляет перебор, но не делает пароль сильным; политика — отдельная задача UI. |
| F4/AAD, F9/ошибки, F10/адрес | см. R3–R5 | — |

## 4. Крэш-дрилл

`crates/core/tests/migration_crash.rs`, фича `crash-injection` (в релиз не
попадает, включается только тестом):

- дочерний процесс запускает `SeedStore::migrate_legacy` и абится в M0, M1, M2,
  M3, M4 или M5; маркер-файл доказывает, что достигнута именно эта точка;
- после каждого обрыва проверяются: ожидаемый набор файлов, отсутствие слабых
  копий, тот же seed и адрес, разблокировка или повторная миграция, затем
  `disable_envelope`;
- 6 точек, ~3,5 с; команда:
  `cargo test -p flint-core --features crash-injection --test migration_crash`.
  На момент ревью обычный прогон — 176 passed, 0 failed, 12 ignored; после
  app-тестов ключа истории, Tor-ack и inbox/history — 184.

Покрытие: границы шагов и состояние «оба файла»/«только конверт»/битый `.tmp`.
Не покрыто: обрыв внутри `write_bytes_atomic` между rename и read-back (тест
симулирует состояние), отказ I/O, потеря питания, межпроцессная гонка.

## 5. Что проверено и не подтвердилось

- Argon2id: параметры ограничены до аллокации, вектор из эталонной реализации
  совпадает; неоднозначной конкатенации в AAD нет.
- AEAD: тег проверяется до разбора plaintext; длины seed/legacy и лимиты файлов
  проверяются; nonce/salt свежие на каждую запись.
- `address_from_entropy` совпадает с upstream на тестовых кошельках; миграция
  теперь сверяет реальный адрес кошелька перед удалением seed.
- Оракула «пароль верный/битый файл» по AEAD нет; структурные ошибки до KDF.
- Секретов в текстах ошибок/логах проверенных путей нет; пароли в командах
  обёрнуты в `Zeroizing`.
