# KimiDocs — рабочая документация Kimi

> **HISTORICAL:** прежние правила ведения. Актуальные правила — [../README.md](../README.md).

Статус до консолидации 2026-10-28: активная параллельная документация, заведена 2026-10-27.

Каталог хранит подробный журнал действий, рабочий план и материалы, необходимые
для продолжения задачи другим участником или в новой сессии. Эти файлы не заменяют
`docs/status/STATUS.md`, `docs/status/MAINNET_READINESS.md` и отчёты аудита.

## Состав

| Файл | Назначение |
|---|---|
| `WORK_LOG.md` | Хронология действий, команд, результатов, ограничений и следующих шагов. |
| `PLAN.md` | Согласованный порядок разработки, зависимости и измеримые гейты. |
| `../docs/KRead.md` | Краткий публичный трекер: что закрыто, что в работе и какое доказательство получено. |

## Правила ведения

1. Новую запись журнала добавлять в начало `WORK_LOG.md`, сразу после общего
   заголовка и правил. Дату и границы снимка указывать в каждой записи.
2. В журнал включать: цель, изменённые файлы, выполненные команды, итог,
   незавершённые проверки, внешние изменения дерева и следующий шаг.
3. Полный большой вывод команд не вставлять. Сохранять его в `.tmp/`, а в журнале
   указывать путь, итог и нужный диапазон строк. Секреты, seed, пароли и приватные
   ключи не записывать никуда.
4. В `docs/KRead.md` отмечать `[x]` только после получения доказательства:
   ссылка на тест/лог, живой сценарий или внешний документ. Наличие кода само по
   себе не закрывает live-гейт.
5. Разделять формулировки: «исправлено по коду», «проверено тестом», «проверено
   живьём», «подтверждено внешним аудитором». Не заменять одно другим.
6. Прерванный прогон и timeout записывать как незавершённую проверку, а не как
   passed или failed без доказательства.
7. Перед новым контрольным прогоном фиксировать снимок. Во время него не менять
   исходники; внешние изменения отмечать отдельно.
8. При смене плана сначала объяснять причину в `WORK_LOG.md`, затем менять
   `PLAN.md` и `docs/KRead.md` согласованно.

## Границы проекта

- Рабочий корень — `C:\DHW`.
- Не сканировать `target/`, `.node/`, `vendor/`, `archV/`, `dist/`, `data/`,
  `.tmp/` и `archive/` без отдельной необходимости.
- Mainnet-каталоги и реальные средства не трогать. Основной стенд — testnet.
- Крупные удаления и перемещения без явного согласия запрещены; перед перезаписью
  нужна копия.
- Текущее предупреждение `DEV BUILD` сохраняется до выполнения официальных гейтов.
