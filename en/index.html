Features

What the wallet does

Non-custodial

Seed and password stay with you. Restore from 24 words into a clean directory: full scan, address comparison with the previous one, honest spendable / awaiting / total / immature / locked states.

Two backends

The embedded grin-wallet from the pinned fork, or a managed grin-wallet RPC. Capability decides which actions are available; the UI does not guess.

Full Slatepack cycle

send → receive → finalize → post → on-chain confirmation. Safe cancel and retry: an unfinished operation continues after a restart, and a retry never signs a second time.

Scan and history

Node, full scan, balances, transaction history and continuation of unfinished transfers. No connection is an explicit status, not a “zero balance”.

Encrypted messages

Contacts, history, durable inbox/outbox. Delivery via relay or direct onion over Tor. The owner API is never exposed.

Native UI

Slint: no WebView2, no Node.js for the wallet itself. Mouse and keyboard, scaling, ru/en, monospaced amounts with tabular figures.

Verifiable build

Offline vendor, Cargo.lock, SBOM, delivery SHA-256 and corresponding sources. The build can be reproduced from the archive instead of trusted.

Local data

Profiles and networks are separated, each with its own seed and history. Wallets, node and settings stay as files on your disk.

Development honesty

What exists, what does not, and how we check it

Already works

  • Creating, opening, locking, restoring and backup
  • Profiles with independent seed and history
  • Node, full scan, balances and history
  • Slatepack: send → receive → finalize → post → confirmation
  • Cancel, retry and continuation of unfinished operations
  • Messenger v1: contacts, history, relay and direct onion
  • ru/en, scaling, keyboard flows

Not yet

  • Mainnet release and permission to use real funds
  • External audit and an Authenticode signature
  • iOS and Android apps in stores
  • A background Windows node service
  • A public relay as a service
  • Forward secrecy in messenger (planned for v2)
  • Physical checks D-01…D-10 and disk-full / power-loss failures
324automated tests in CI, 0 failures; live suites run separately
2accepted dependency advisories, 0 unaccepted — the list is public
0promises about mainnet, audit or mobile release dates

If you need a wallet for real money right now, Flint is not it. The project exists to test Grin wallet behaviour in the open: code, tests, evidence and open limitations live in the repository.

Platforms

One domain model, different shells

Windows · now

Slint client, Rust MSVC, portable package with the node, Tor and runtime DLLs. Embedded or managed grin-wallet, local profiles.

iOS · coming soon

GrinFlint is a separate repository with its own acceptance. SwiftUI shell, shared Rust contract, its own lifecycle and Keychain. Desktop checks do not confirm iOS readiness.

Android · coming soon

Plan only. Shared transfer rules and formats are already described, but there is no app and no acceptance.
